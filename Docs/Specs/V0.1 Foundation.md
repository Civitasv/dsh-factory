# V0.1 Foundation

## Objective

Establish repository and architectural boundaries before implementing autonomous SDLC flows.

## Scope

V0.1 defines and validates:

1. a pure Change-centric domain package;
2. an append-only event vocabulary package;
3. a DSH/Cordis adapter seam;
4. GitHub Actions validation;
5. navigable Architecture/Spec/Development documentation.

## Acceptance criteria

### AC-001 — domain independence

`packages/core` and `packages/events` do not import DeepSeek Harness or Cordis.

### AC-002 — evidence-backed gates

Creating a `satisfied` or `failed` Gate evaluation without Evidence is rejected. `pending` and `not_required` remain legal without fabricated evidence.

### AC-003 — event ordering

An event stream must have strictly increasing per-Change sequence numbers. Duplicate or regressing sequence numbers are rejected.

### AC-004 — DSH adapter seam

`packages/runtime-dsh` exposes a conventional Cordis namespace-plugin entry without leaking DSH/Cordis types into domain packages.

### AC-005 — public-repo CI

Pull requests and pushes to `master` run typecheck, lint, and unit tests through GitHub Actions. No CNB files or CNB workflow assumptions exist.

## Non-goals

- persistence backend;
- Change Graph query engine;
- Context Compiler;
- worker scheduler;
- GitHub/CI adapters;
- browser/computer-use QA;
- release automation;
- production observation;
- UI.
